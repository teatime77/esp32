# C数値カーネルの概要と作業計画

Pythonプログラム全体をPython VMで動かし、数値計算の関数をCへ変換して高速化する。配列の準備や通常の処理はPythonで書き、計算ループには`@kernel`と`launch()`を使う。

現在は構文・型解析、共通Cの生成、ブラウザ用VM・Cコンパイラーとの接続まで実装済み。ブラウザではPythonBlockの実行先を「ブラウザ」にしてStartを押す。Openから`numeric-kernel.py`を読み込むと使用例を確認できる。[資産生成と利用方法](../browser/README.md)を参照する。

## 使い方

`@kernel`を付けた関数に、配列の1要素分の計算を書く。`launch()`が要素数を指定し、まとめて計算を実行する。

```python
import numpy as np

@kernel
def saxpy(i: int, a: float, x: InF32, y: InF32, out: OutF32) -> None:
    out[i] = a * x[i] + y[i]

x = np.zeros(1000, dtype=np.float32)
y = np.zeros(1000, dtype=np.float32)
out = np.zeros(1000, dtype=np.float32)

launch(saxpy, len(out), 2.0, x, y, out)
```

`launch(saxpy, n, ...)`は、`i = 0`から`n - 1`までの計算を実行する。`n`には非負の整数を指定する。引数の式は左から右へ一度ずつ評価する。計算が完了すると、Python VMが次の処理へ進む。

## 関数と配列の書き方

カーネルはモジュール直下に定義し、引数と戻り値に型を付ける。先頭引数は実行インデックスで、値は実行側が設定する。`launch()`にはカーネル名、要素数、残りの引数を位置引数で渡す。

| 型 | 意味 |
|---|---|
| `int` | 符号付き32bit整数 |
| `float` | 単精度浮動小数点数 |
| `InF32` | 読取り専用の連続した1次元float32配列 |
| `OutF32` | 書込み専用の連続した1次元float32配列 |
| `-> None` | 出力配列へ結果を書き込む関数 |

`kernel`、`launch`、`InF32`、`OutF32`は組込み名として使う。

各実行は、自分の実行インデックスに対応する`out[i]`へ書き込む。実行インデックスと配列引数は関数内で固定し、入力と出力には別々の配列を用意する。複数の出力にもそれぞれ別の配列を使う。入力同士では同じ配列を共有できる。

添字と要素数の妥当性はプログラム側で保証する。条件分岐で書込みを省いた要素や、指定要素数より後ろの要素は、元の値を保つ。各要素の計算は独立させ、実行順序に依存せず結果が決まるように書く。

## カーネルで使う機能

| 種別 | 対応する機能 |
|---|---|
| 演算 | `+`、`-`、`*`、`/`、単項符号、数値比較 |
| 論理 | 比較結果のboolと、boolに対する`and`・`or`・`not` |
| 制御 | ローカル変数、代入、if/elif/else、有限なfor/while、break/continue、値なしreturn |
| 配列 | 入力の1次元添字アクセス、出力の`out[i]`、`len(array)` |
| 組込み関数 | 数値の`abs`、2引数の`min`・`max`、intからfloatへの`float`変換 |
| 補助関数 | 型注釈付きの純粋なスカラー関数。引数と戻り値はintまたはfloat |

整数同士の`+`・`-`・`*`はint32、floatを含む演算と`/`はfloat32で計算する。ローカル変数は固定の型を持つ。forには整数の`range`と正の整数定数のステップを使う。whileには、整数の制御変数・不変な上限・末尾の一定量の更新で有限性を解析できる形を使う。利用できる形の詳細は[解析処理の仕様コメント](../../../../uroa/diagram/ts/python/kernel.ts)を参照する。

## 実行方式

数値計算にはfast mathを有効にした`unsafe-fast-v1`を使う。添字・オーバーフロー・ゼロ除算・非有限値はプログラム側の責任とし、計算結果は各環境の最適化されたC/Wasm演算に従う。配列にはNaN・Infが含まれる場合がある。

カーネルは同期的に最後まで実行する。VMの停止要求への応答と通信・機器処理の再開は、計算から戻った後になる。デバッガーでは`launch()`の前後を扱う。

起動時に登録情報と成果物のハッシュを照合し、呼出し時に引数の型、配列形式、入出力の共有状態を確認する。Cへ渡す配列は呼出し中だけ借用する。

## 環境ごとの構成

| 環境 | Cのビルドと接続 | 配列の受渡し |
|---|---|---|
| ESP32 | 生成CをPlatformIOでファームウェアへ組み込む | VMの配列を直接借用 |
| ブラウザ | wccでWasmへ変換し、Binaryenで最適化。同じWorker内のVMと接続 | 計算前に入力・出力の初期内容をコピーし、完了後に出力を反映 |
| Colab | 生成Cを共有ライブラリーにしてVMへ登録 | 同一プロセスのVM配列を直接借用 |

配列の確保と管理は自作NumPyが担当する。ESP32とColabではカーネルのCコンパイルに`-O3 -ffast-math`を指定する。ブラウザでは計算用WasmにBinaryenの最適化とfast mathを適用する。ブラウザ用ツールの固定版と導入方法は[選定記録](browser-c-compiler.md)を参照する。
